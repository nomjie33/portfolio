Data engineering

NYC TLC Yellow Taxi — ETL Pipeline & OLAP Dashboard

A data warehouse over the NYC Taxi & Limousine Commission trip records. I built the four-stage ETL pipeline (load, profile, transform, validate) for a four-person team, ingesting twelve monthly Parquet files — 38,310,226 rows — into a star-schema PostgreSQL warehouse. 38,307,435 rows loaded (99.993%), with all 2,791 rejects logged against reason codes such as drop-off before pick-up and trips over 24 hours. I imputed defaults for 1,309,356 flex-fare records and deliberately kept 376,883 negative-total and 773,457 zero-distance trips as published events, then added a validation step reconciling source rows to loaded plus rejected. Raw data was staged unindexed and indexes deferred to avoid bulk-load bottlenecks.

On top of it, I co-built an interactive dashboard showing monthly revenue and trip trends, busiest weekdays and times of day, and vendor performance across boroughs, with filters for revenue, distance and passenger metrics. The team's secondary index and query restructuring cut median drill-down query time by 78–86% — 9.2s to 2.0s on one machine — verified with EXPLAIN ANALYZE.

Networking

MTGNP — Multiplayer Network Protocol

A two-player networked card game implementing a 25-message protocol over TCP, written in Python with the standard library only. The server is built in four strict layers — transport, protocol, session/lifecycle and a pure rules engine that never touches a socket — with all game state owned by a single thread fed from a queue. I built the client (MVC: networking, cached state, CLI rendering and command parsing with sequence-number echo) and the combat engine on the server side: attackers, blockers, damage ordering and first-strike resolution.

Research · Analytics

Nested Navigation Study — Analysis Pipeline

The data-analysis pipeline for a within-subjects usability experiment measuring how three navigation patterns — deep hierarchical, mega-menu and nested dropdown — affect item-finding speed and error recovery across 15 participants. One command validates, cleans, derives the trial metrics (error count, recovery time, find time), produces descriptive tables and twelve figures, fits the inferential models, and writes the hypothesis decisions and a draft results section. It ships with a synthetic data generator — including a deliberately corrupted variant with injected faults used to test the validator — and 43 tests.
